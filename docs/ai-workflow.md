# AI 에이전트와 함께 만든 과정

이 프로젝트는 Claude 기반 브라우저 에이전트(Aside)에게 자연어로 요구사항을 주고,
에이전트가 코드 작성 → Apps Script 편집기에 삽입 → 실행 → 시트/캘린더/메일을 직접 열어 검증하는 루프를 돌리며 만들었습니다.
아래는 실제 흐름을 시간 순으로 정리한 것입니다. 사람이 결정한 것과 AI가 한 것을 구분했습니다.

## AI가 틀렸거나 삽질한 것 (그리고 어떻게 잡았나)

솔직하게 적는 편이 더 설득력 있다고 판단해 남깁니다.

1. **첫 전체 동기화가 6분 타임아웃**
   원인은 코드가 아니라 `SpreadsheetApp.getUi().alert()`. 편집기에서 실행했는데 열려 있던 시트 탭에 모달이 떠서 응답을 기다리며 블로킹. AI가 시트 탭을 확인해 원인을 찾고 `toast()`로 교체. 부산물로 6분 제한 대응(시간 예산 + 이어서 실행)이 들어감.
2. **클립보드 붙여넣기가 엉뚱한 셀에**
   테스트 값을 F59에 넣으려다 병합된 제목 셀 A1에 덮어씀. Undo가 안 먹혀 Apps Script `RichTextValue`로 원문과 부분 빨간색 서식까지 복원. 이후 셀 입력은 키보드/스크립트로만.
3. **드롭다운 셀에 키보드 입력이 이어붙음** (`처리중대기`)
   수동 입력 대신 "목록에 없는 값은 정리" 규칙을 스크립트에 넣어 데이터 자체를 방어.
4. **쿠키 기반 시트 읽기가 병합 셀에서 값이 어긋남**
   외부 도구 결과를 믿고 "빈 행"이라 판단했다가 실제로는 요청이 있던 행이었음. 이후 판단은 스크립트 내부 `getValues()`나 실제 화면 스크린샷으로만.
5. **날짜가 하루씩 밀려 보임 (시간대)**
   요청표를 새로 그린 직후 내보낸 파일에서 모든 날짜가 전날 오후로 찍혀 있었다. 스크립트 시간대(한국)와 시트 시간대가 달라, 스크립트가 만든 한국 자정이 시트에서는 전날로 저장된 것. 스크립트끼리는 같은 시간대로 다시 읽어서 로직 검증은 전부 통과했고 사람 눈에만 틀린 상태였다. 실제 파일을 내보내 "사람이 보는 값"으로 검증하는 단계에서 잡았고, 날짜를 문자열로 쓰도록 고친 뒤 강제 재생성.
6. **오늘 날짜에 걸린 요청**
   적용 당일 근무일정상 근무일이 아닌 날에 요청 4건이 들어와 있었다. 삭제하면 선생님들이 요청 흔적을 잃으므로 "조정 필요" 구역으로 옮기고 캘린더 제목에 표시만 하는 쪽을 택했다. 근무일정이 틀린 경우라면 근무일정만 고치면 원래 칸으로 돌아간다.
7. **요구사항 해석**
   "이미 지난 경우는 완료 및 보류인데 이건 내가 할게"를 처음엔 "완료도 수동"으로 해석 → 확인 질문 → "완료는 자동" 으로 정정.

## 내가 얻은 것

- **AI에게 시킬 때 중요한 건 코드가 아니라 검증 루프**: 캘린더를 직접 열어보고, PDF를 이미지로 렌더링해서 보고, 테스트 값을 넣었다 지우는 것까지 시켜야 결과를 믿을 수 있다.
- **요구사항은 3번 바뀌었다**: 처음부터 완벽한 스펙은 없다. 상태 규칙은 "등록 여부 → 시간 기준 → 완료 자동"으로 진화했고, 코드가 작고 시트에 붙어 있어서 매번 10분 안에 반영됐다.
- **데이터 모델이 먼저**: 행정 메모와 서류용 활동을 한 열에 두면 서류가 오염된다. 열을 나누는 게 코드로 필터링하는 것보다 낫다.
- **배포 가능성은 처음부터**: 이름/이메일이 코드에 박혀 있으면 아무리 잘 만들어도 남에게 줄 수 없다. 서명 이미지도 같은 원칙으로 설정 탭에 두었다.
- **사람이 맞추는 두 표는 결국 어긋난다**: 동기화 규칙을 더 만드는 대신 한쪽을 다른 쪽에서 파생시키면 불일치가 구조적으로 사라진다.
